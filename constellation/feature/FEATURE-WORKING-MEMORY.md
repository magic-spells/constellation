# Working memory (`.constellation/`)

Cards are durable architecture. A session also needs short-term memory: what is in
flight, in which worktree, held by which agent, what is next, what waits on the user,
what was decided tonight. That state lived in a hand-edited scratchpad and every update
was a regex over the file. This gives it first-class tools, so an agent reads it at
session start and after every compaction and edits single items by ID.

The forcing function is compaction. A compaction summary is generated by a model from
the transcript, and nothing in CLAUDE.md or a hook can steer what it keeps (`PreCompact`
can only block; `custom_instructions` is null on auto). So the state that must not depend
on the summary is written to disk the moment it changes and re-read from disk right after
the summary lands.

## Scope

- In: `src/core/working.ts` (parse/serialize, per-type ID allocation, FOCUS supersede,
  daily log, worktree-aware folder resolution, locked atomic writes, `working_init`);
  the `working_list` / `working_set` / `working_drop` / `working_log` / `working_init`
  MCP tools; the same `{header, items}` payload embedded in `orient` under `working`;
  `init_plan { working }`; `constellation working` + `working install-hook`;
  `currentBranch()` in [[FILE-GIT]]; the `.constellation/CLAUDE.md` template in
  [[FILE-SCAFFOLD]]; `.constellation` added to the code-metrics walk skip list in
  [[FILE-CODE]]; the skill, README and `INSTRUCTIONS` text.
- Out: anything that would make an item a card. No index, graph, lint, stale report,
  `diff_plan`, atlas, `check_sync` or viewer city entry; no status enum, no versions, no
  history in the file (the log is the history); the folder never moves under
  `constellation/`. A read-only "Working" panel in the viewer is a later change.

## Format

One header line plus one line per item, grouped by type in fixed order — GOAL,
CONSTRAINT, PLAN, FOCUS, TASK, QUESTION, IDEA, DECISION. Empty sections are omitted.

```
Updated 2026-09-17 06:56 · branch `release/1.0.0` @ 62da1b5 · next G3 C11 P4 F2 T15 Q8 I9 D12

## TASK
- T12 [4] Stripe webhook — wt stripe-webhook, 148846a, opus a2c1 → merge
```

IDs are `<prefix><n>`, allocated per type from the header counters, never reused and
never renumbered; type is fixed at creation (`TYPE_IMMUTABLE`). `[1-5]` is importance —
what gets cut first if the set grows. FOCUS is singular: a new F drops the old one and
logs the supersede. Body text is one line (`BAD_TEXT` on a newline); over 160 characters
still writes but returns `warnings: ["long: T12"]`, as does a set past 25 items. The
header is rewritten on every write; every other line is byte-preserved.

## Acceptance

- The SessionStart hook prints the set at startup, resume, compact and clear; `orient`
  returns the same `{header, items}` for MCP-only clients, and omits the key when the
  folder does not exist.
- `working_set` returns the allocated IDs and the new header; `working_drop` with a
  reason removes the lines and writes one log line.
- `working_log` called from a linked worktree lands in the main checkout's log.
- `constellation working` prints nothing and exits 0 where there is no folder, so the
  hook is safe to install globally.
- `constellation lint` and the viewer are unaffected by anything in `.constellation/`.
